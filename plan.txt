# Synodic Server - Open Source Education Management System

## Overview
Synodic Server is a self-hostable education management system that powers both Synodic Learn (student interface) and Synodic Teach (staff interface). Built with Nuxt 3, TypeScript, and Tailwind CSS, it provides a modern, secure, and feature-rich platform for educational institutions.

## Technical Stack Details

### Frontend
- **Nuxt 3**
  - Server-side rendering for SEO
  - Auto-imports for components and composables
  - File-based routing
  - Built-in state management
  - API routes integration

- **TypeScript**
  - Strict type checking
  - Interface definitions for all data structures
  - Type-safe API calls
  - Enhanced IDE support

- **Tailwind CSS**
  - Custom theme configuration
  - Responsive design utilities
  - Dark mode support
  - Custom animations
  - Component-specific styles

- **UI Components**
  - Headless UI for accessible components
  - Heroicons for consistent iconography
  - Custom form components
  - Modal dialogs
  - Dropdown menus
  - Toast notifications

- **Animations**
  - GSAP for complex animations
  - AOS for scroll animations
  - Page transitions
  - Loading states
  - Micro-interactions

### Backend
- **Authentication**
  - JWT (jose) for secure tokens
  - Refresh token rotation
  - Role-based access control
  - Session management
  - Password hashing with bcrypt

- **Data Storage**
  - Encrypted JSON files
  - File-based versioning
  - Backup system
  - Data validation
  - Schema enforcement

## Data Models

### User
```typescript
interface User {
  id: string;
  email: string;
  password: string; // hashed
  role: 'student' | 'staff' | 'admin';
  firstName: string;
  lastName: string;
  createdAt: Date;
  updatedAt: Date;
}
```

### Course
```typescript
interface Course {
  id: string;
  title: string;
  description: string;
  content: string; // markdown
  teacherId: string;
  resources: Resource[];
  schedule: Schedule[];
  createdAt: Date;
  updatedAt: Date;
}
```

### Assessment
```typescript
interface Assessment {
  id: string;
  courseId: string;
  title: string;

  dueDate: Date;

  updatedAt: Date;
}
```

```typescript
interface Notice {

  priority: 'low' | 'medium' | 'high';
  startDate: Date;

  updatedAt: Date;
}
```

## API Endpoints

### Authentication
```
POST /api/auth/register-admin    # Only for first admin setup
POST /api/auth/invite            # Admin only - Generate invite codes
POST /api/auth/register          # Register with valid invite code
POST /api/auth/login
POST /api/auth/refresh
POST /api/auth/logout
```

### Learn API
```
GET /api/learn/courses
GET /api/learn/courses/:id
GET /api/learn/assessments
GET /api/learn/assessments/:id
```

### Authentication Flow
1. Initial Setup
   - First admin registration with secure setup key
   - Setup key stored in environment variables
   - One-time use only

2. Invite System
   - Admins generate invite codes
   - Invite codes are time-limited
   - Single-use codes
   - Role-specific invites (staff/student)
   - Invite tracking and audit logs

3. User Registration
   - Validate invite code
   - Create user account
   - Assign appropriate role
   - Generate initial credentials

4. Login Flow
   - User submits credentials
   - Server validates and generates JWT
   - JWT stored in secure HTTP-only cookie
   - Refresh token stored in secure HTTP-only cookie
   - Access token rotation on refresh

### Invite Code Structure
```typescript
interface InviteCode {
  code: string;          // Unique invite code

  createdBy: string;     // Admin ID
  createdAt: Date;
  expiresAt: Date;

  usedBy?: string;       // User ID if used
  usedAt?: Date;
}
```
